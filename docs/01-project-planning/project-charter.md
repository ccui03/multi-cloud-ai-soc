# 项目总体方案书（Project Charter）

- 项目名称：Multi-Cloud AI SOC
- 文档版本：1.0（初稿）
- 状态：待评审
- 日期：2026-11-26

## 1. 背景

企业安全日志分散在不同云厂商和安全产品中，字段格式、查询方式和告警机制不一致。安全运营人员需要在多个控制台之间切换，手工关联攻击源、请求行为、资产和防护结果，调查过程耗时且难以标准化。

本项目计划建设统一的多云 WAF 安全运营能力，并引入 AI Agent 辅助告警研判、攻击调查和报告生成。

## 2. 项目目标

### 业务目标
- 减少跨云安全日志调查中的重复人工操作。
- 提高告警分析的一致性和可解释性。
- 形成可追溯的安全事件调查记录。
- 在严格权限和审批控制下验证自动化响应。

### 技术目标
- 以适配器方式接入不同云厂商日志。
- 建立规范化事件模型并保留原始数据。
- 通过规则、查询和 Agent 工作流协同分析。
- 提供统一 API 和 Web 界面。
- 支持组件替换、水平扩展和审计。

## 3. 初始交付范围

1. 一个优先云 WAF 数据源的日志接入 PoC。
2. 原始日志存储、字段解析和标准化。
3. 基础检索、聚合和告警规则。
4. 告警分诊与攻击调查 Agent。
5. 事件分析报告。
6. 一种低风险或需审批的响应动作演示。

多云全面接入、生产级高可用和无人值守自动封禁不属于第一阶段承诺。

## 4. 关键使用场景

- 单个来源 IP 在短时间内触发大量 WAF 拦截。
- 同一攻击源针对多个域名或应用发起扫描。
- WAF 告警需要关联威胁情报、历史事件或其他安全日志。
- 分析人员需要快速获得攻击时间线、证据摘要和处置建议。
- 安全负责人需要生成事件报告和趋势摘要。

## 5. 主要成功指标（PoC 指标，待确定阈值）

- 日志接入成功率和端到端延迟。
- 关键字段解析准确率。
- 告警去重/归并效果。
- Agent 调查结果的证据覆盖率和可复核性。
- 报告生成耗时。
- 工具调用成功率、审批覆盖率和审计完整性。
- 误报、漏报及错误响应情况。

## 6. 约束与假设

- 通过云厂商正式 API、日志服务或受支持的日志投递方式获取数据。
- 所有访问凭据使用 Secret 或安全凭据管理机制，不进入 Git。
- 首期以只读调查为主，写操作默认关闭或要求人工审批。
- 具体云厂商、日志量、保留周期、预算和部署环境尚待确认。
- 现有 SIEM 能力优先评估复用，不预设替换。

## 7. 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 云厂商日志字段差异 | 统一分析困难 | Adapter + 规范化映射 + 原始字段保留 |
| 日志量和成本超预期 | 存储/检索成本增加 | 采样、分层存储、聚合和保留策略 |
| LLM 幻觉 | 错误研判 | 要求证据引用、结构化输出和人工复核 |
| Prompt Injection | Agent 被日志内容诱导 | 将日志视为不可信数据，工具参数校验 |
| 自动响应误封 | 业务中断 | 审批、TTL、回滚、白名单和审计 |
| 凭据泄露 | 云资源风险 | 最小权限、短期凭据、Secret 管理 |

## 8. 角色与职责

初期由项目负责人兼任需求、架构和开发协调；后续按需要明确安全运营、平台开发、云平台和测试职责。

## 9. 项目治理

- GitHub Repository：保存正式文档、代码和变更历史。
- GitHub Projects：管理任务状态和里程碑。
- Issues：记录可执行任务、缺陷和讨论。
- ADR：记录重要架构决策。
- 文档更新应经过评审确认。

## 10. 待确认事项

- 首个 PoC 云 WAF：阿里云、腾讯云、Azure、AWS 或其他？
- 是否复用现有 QRadar/SIEM？是否有可用 API？
- 日志规模：日均条数、峰值 EPS、单条大小。
- 计划部署位置：本地服务器、云主机还是 Kubernetes？
- 是否允许调用外部 LLM API？是否有数据出境或隐私限制？
- PoC 预算和预期完成周期。
