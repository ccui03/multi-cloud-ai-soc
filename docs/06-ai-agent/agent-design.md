# AI Agent 设计基线（规划阶段）

- 版本：2.0
- 状态：目标设计；尚未进入完整实现阶段

## 1. Agent 在产品中的定位

AI Agent 是安全分析人员的辅助调查和报告层，不是日志采集器、规则引擎或最终安全决策者。Agent 只消费经过查询、筛选、标准化和脱敏的数据，通过受控工具补充证据。

## 2. 目标工作流

```text
Alert / Analyst Request
        |
Input Validation & Scope
        |
Triage
        |
Investigation Planning
        |
Read-only Evidence Retrieval
        |
Correlation / Hypothesis Verification
        |
Timeline & Findings
        |
Report Generation
        |
Human Review / Feedback
```

## 3. 工作流节点

| Node | 职责 | 输入 | 输出 | 权限 |
|---|---|---|---|---|
| Input Guard | 校验事件 ID、时间范围和查询范围 | 用户请求/告警 | 合法调查任务 | 无数据源直连 |
| Triage | 分类、摘要、优先级建议 | 标准化事件/告警 | 分诊结果 | 只读 |
| Planner | 生成调查步骤和待验证假设 | 分诊结果 | 结构化调查计划 | 不执行任意工具 |
| Evidence Retrieval | 查询事件、源日志和统计结果 | 受限查询参数 | 证据集合 | 只读 allowlist |
| Correlation | 整理实体、时间线和跨源关联 | 证据集合 | 关联结果/假设 | 只读 |
| Verification | 检查假设是否被证据支持 | 假设 + 证据 | 支持/反证/未知 | 只读 |
| Report Writer | 生成报告和建议 | 已验证发现 | 结构化报告 | 不执行写操作 |
| Human Review | 人工确认、修正和反馈 | 报告/建议 | 审核记录 | 人工操作 |

以上先作为单个 LangGraph 工作流中的节点，不拆分成多个独立 Agent 服务，除非后续规模和边界证明有必要。

## 4. 工具边界

允许的工具类别：
- 标准化事件查询。
- 告警/案例查询。
- 按限定时间、数据源和实体回查源端日志。
- 源端聚合统计和 Top-N 查询。
- 查询 Schema/字段定义和数据源能力信息。

工具必须具备：
- allowlist 和严格输入/输出 Schema。
- 最大时间范围、最大返回量、超时和调用预算。
- 调用身份、参数摘要、结果引用和审计记录。
- 统一错误处理，不向模型泄露云凭据或 SDK 内部敏感信息。

Agent 不允许：
- 任意执行厂商查询 DSL 或任意代码。
- 读取无限时间范围或无限量日志。
- 自行更改字段注册表或检测规则。
- 直接调用厂商写 API、封禁 IP 或修改 WAF 策略。

## 5. 输出契约

报告至少包含：
- summary：事件摘要。
- severity：风险等级及理由。
- confidence：置信度及依据。
- evidence：事件 ID、来源、时间和支持理由。
- timeline：按时间排序的关键活动。
- hypotheses：攻击假设、支持证据、反证和未知项。
- recommended_actions：建议动作、预期效果和风险。
- limitations：数据范围、缺失字段和调查局限。
- needs_human_review：是否需要人工复核。

模型输出必须通过 JSON Schema/类型校验；证据引用必须能在系统中解析。

## 6. 安全与可靠性

- 所有日志内容都是不可信数据，不得成为系统指令或工具授权。
- URL、Header、Cookie、User-Agent、请求参数和请求/响应体按敏感级别脱敏。
- 不向模型传递 AK/SK、SecretId/SecretKey、凭据文件或完整云 API 响应。
- 先做确定性过滤、聚合和规则分析，限制模型上下文。
- Agent 节点需记录模型版本、提示模板版本、工具调用和失败状态。
- 对模型超时、无效结构化输出和证据缺失设计重试/降级。
- 结论必须区分事实、推断和未知，不允许将相关性直接表述为因果关系。

## 7. 评估计划

建立脱敏评估集，至少覆盖：
- 正常访问与误报。
- WAF 规则命中、阻断、挑战、观察/测试模式和放行。
- Bot、扫描、CC/频率异常等行为。
- 多 IP、多域名和跨云相似事件。
- 字段缺失、未知枚举、时间偏差和重复日志。
- Prompt Injection 样本和恶意构造日志内容。

评估指标：
- 证据引用正确率。
- 事实错误/无依据结论比例。
- 严重性判断一致性。
- 调查步骤有效率。
- 报告完整度和人工修订比例。
- 单次调查 Token、成本和端到端耗时。

## 8. 后续响应能力

响应规划与响应执行分离。执行阶段必须经过独立策略层、权限校验、人工审批、TTL、回滚和结果核验。首期 Agent 仅输出建议，不执行云端写操作。

## 9. 分层研判 Agent 工作流（v2.1 补充）

### 9.1 工作对象
Agent 默认输入是 Alert Group 或 Security Incident 的 Evidence Pack，而不是原始日志流。单条日志仅在需要验证假设时按需下钻。

### 9.2 推荐工作流
1. Intake：读取事件候选、聚合统计和上下文，检查数据范围。
2. Evidence Validation：验证证据引用、字段语义状态和时间范围；缺口必须标记。
3. Triage：给出初步风险和优先级，不把初步结论当最终判断。
4. Investigation Planning：列出待验证假设、所需证据和最小查询范围。
5. Evidence Retrieval：通过受控只读工具查询标准事件、源端聚合或少量原始样本。
6. Hypothesis Testing：同时寻找支持证据和反证，检查正常业务解释、代理/NAT 共享来源、测试模式等替代假设。
7. Verdict：输出分层结论、置信度、严重性、影响范围和未知项。
8. Recommendation Draft：仅在证据支持时生成 WAF 策略优化建议，说明范围、误放风险、验证和回滚考虑。
9. Human Review：安全人员确认/修正研判与建议；人工执行不由 Agent 发起。
10. Feedback Capture：记录最终分类、建议是否采纳、人工执行结果和后续观察结果。

### 9.3 结论与置信度
verdict：confirmed_malicious、likely_malicious、likely_legitimate、confirmed_legitimate、inconclusive。Severity 表示潜在影响，Confidence 表示证据对结论的支持程度，两者必须分开。输出必须区分 observation、inference 和 unknown。高严重性但低置信度的事件仍可能需要优先人工调查。

### 9.4 反误报与证据要求
- “正常业务”判断必须有正向依据，不能仅因未发现攻击证据就判定正常。
- 检查与结论相反的合理假设；证据矛盾时降低置信度或输出 inconclusive。
- 不能仅凭 IP 相同合并攻击活动。
- WAF 命中、WAF 拦截、HTTP 响应码和后端实际受影响是不同事实。
- 放宽规则建议必须说明规则/路径/参数范围、样本和统计依据，以及可能的绕过风险。
- 不得把有限样本或抽样结果表述为全部流量的完整事实。

### 9.5 人工反馈闭环
记录原 AI verdict/severity/confidence、人工最终 verdict 和理由、建议接受/拒绝/修改状态、外部变更单引用、人工执行人/时间、变更后观察窗口及效果判断。反馈用于离线评估、阈值调优和提示模板改进；未经评估与审批，不得把单次反馈直接转为生产检测规则或训练标签。

## 10. AI Copilot 对话体验与安全约束（v2.2 补充）

### 10.1 两种对话入口
- 独立 AI 助手：用户从主导航打开会话，明确选择或输入数据源、时间范围和调查目标。
- 上下文 Copilot：用户从日志、告警组或事件详情打开，自动附带当前对象上下文，并在界面持续显示当前上下文。

### 10.2 对话能力
- 自然语言转受限日志查询意图。
- 解释日志字段、WAF 规则命中、告警聚合和事件关联。
- 对选定告警组/事件进行证据驱动调查。
- 支持多轮追问、假设验证、报告生成和策略建议草稿。
- 回答中的证据引用可定位到 UI 中对应日志/告警/事件。

### 10.3 查询计划协议
Agent 先产生结构化 Query Intent，包括数据源范围、时间窗口、过滤字段、聚合维度、返回字段、最大结果数和查询目的。Query Planner 校验权限、能力、成本和限制后执行。模型不能自行执行 SQL 或厂商 DSL。对范围不清楚或高成本请求，应先澄清或请求用户确认。

### 10.4 对话呈现契约
每个分析回答至少包含：问题理解、数据范围、查询/调查摘要、结论、严重性、置信度、事实、推断、支持证据、反证、未知项和下一步建议。简单日志查询可简化格式，但仍需提供数据范围和证据来源。模型无法取得证据时必须明确说明，不得虚构查询结果。

### 10.5 会话与权限
会话保存用户和数据范围元数据；每次工具调用重新校验权限，不因会话创建时有权限就永久授权。会话历史中的日志内容仍是不可信数据。跨事件切换时显式更新上下文，防止旧上下文污染新调查。

## 11. AI Drawer 与独立 Workspace 上下文规则（v2.3）

- AI Drawer 和独立 AI Workspace 共享同一 Session、Investigation 和 Evidence 引用。
- Drawer 从业务页面启动时，只接收经过服务端授权的 Context Envelope。
- 上下文必须标识其类型：记录引用、告警组、事件、保存查询或过滤摘要；不得把过滤摘要描述成完整日志集合。
- 用户明确添加、移除或切换上下文后，服务端记录上下文快照版本；页面导航本身不改变会话上下文。
- Agent 每次调用工具重新验证会话用户、数据源权限和对象访问权。
- 关闭 Drawer 不代表取消 Agent 任务；取消调查必须由用户显式触发。
- 从 Drawer 升级到 Workspace 时沿用相同 Session ID 和证据引用，不能复制出一份不一致的调查历史。

## 12. 双入口分析任务：手动 + 定时自动（v2.5）

### 12.1 设计原则
手动分析与定时自动分析是同一 AI 威胁分析引擎的两种任务触发方式，不是两套 Agent 或两条独立分析流水线。两种入口统一生成 Analysis Task，进入相同的范围校验、数据查询、预筛选、聚合、Evidence Pack、LangGraph 研判、结果持久化和审计流程。

### 12.2 手动分析流程
1. 用户选择数据源、时间范围和可选过滤条件，或从日志页面选择记录/行为簇。
2. 系统预览查询范围、预计记录量/查询成本（若可估算）、结果上限和脱敏规则。
3. 用户确认后创建 manual Analysis Task。
4. 引擎执行受控查询、统计/规则预筛选和聚合；必要时按需下钻原始记录。
5. AI 输出结构化威胁研判报告，UI 展示任务状态、分析范围、证据和结论。

### 12.3 定时自动分析流程
1. 每个数据源独立配置启用状态、时间间隔、窗口长度、重叠窗口、最大查询量/成本预算和分析阈值。
2. Scheduler 根据数据源 Checkpoint 创建 scheduled Analysis Task；Checkpoint 与分析任务状态分离，避免任务失败导致游标错误前移。
3. Query Service 读取上次成功水位至本次窗口结束的日志，保留迟到日志重叠窗口，并使用稳定 Fingerprint/幂等键去重。
4. 对日志做确定性规则筛选、统计聚合和行为簇构建；无显著候选时可记录“已检查、未发现达到阈值的候选”，不必调用 LLM。
5. 对达到触发条件的候选生成 Evidence Pack，调用同一 LangGraph 工作流研判。
6. 结果写入分析记录；高风险或高置信候选在 UI 标记为待关注/待人工复核，不自动执行封禁或策略修改。

### 12.4 Analysis Task 统一状态
建议状态：queued、running、waiting_for_budget、completed、completed_with_warnings、failed、cancelled。任务需记录 trigger_type（manual / scheduled）、source_ids、时间范围、查询计划版本、数据量/样本量、截断状态、消耗、模型/Prompt/Workflow 版本、Evidence Pack 引用和错误摘要。重复调度使用幂等键避免同一数据源和窗口重复创建有效任务。

### 12.5 失败恢复与成本控制
- 每个数据源独立调度和 Checkpoint；一个数据源失败不阻塞其他数据源。
- 仅在查询和结果持久化成功后推进成功水位；失败任务可重试，重试必须幂等。
- 使用窗口重叠处理迟到日志，并通过 Fingerprint 去重；重叠时长需根据真实日志延迟观测配置。
- 设置每数据源查询频率、最大时间范围、最大返回量、LLM 调用预算和每日成本上限。
- 对超预算任务跳过、延后或降级为统计分析，并记录原因；不得静默丢弃。
- 调度任务支持暂停、恢复和手动补跑；补跑必须指定范围并受相同预算控制。

### 12.6 安全边界
Scheduler 只创建任务，不持有厂商凭据；查询由已有受控 Query Service/Provider Adapter 执行。Agent 仅有只读工具。定时自动分析不是自动响应，任何 WAF 策略变更仍由人工在外部流程执行。

### 12.7 验收标准
- 手动与定时任务生成相同结构的 Analysis Task，并复用相同分析工作流。
- 两种任务均展示数据源、时间范围、查询/样本数量、截断状态、耗时、成本和分析结果。
- Checkpoint 按数据源隔离；失败、重试、重复调度和迟到日志处理正确。
- 无候选时可不调用 LLM，并记录扫描结果与原因。
- 预算耗尽时有明确状态/告警，不会无限查询或无限调用模型。
- 暂停/恢复/补跑可控且可审计；Agent 不执行云端写操作。

## 13. 核心研判图与 Evidence Pack 契约（v2.2）

详细字段和流程以 [核心分析引擎技术设计](../07-core-analysis-engine/core-analysis-engine-design.md) 为准。本节确立 Agent 层边界：

- LangGraph 采用 Evidence Validation → Threat Hypothesis → Evidence Analysis → Counter-Evidence →（条件）Context Enrichment → Threat Classification → Report Generation → Persist & Audit。
- 不合格证据包进入数据质量/补充证据分支；预算耗尽、查询失败或证据矛盾不得伪装成无威胁。
- 只读工具包括受控日志查询、事件详情、行为上下文、WAF 规则元数据、历史基线和关联候选查询。工具调用必须经过后端权限、参数、范围、预算、脱敏和审计。
- Agent 不持有云凭据，不直接访问任意日志范围，不执行 WAF 写操作。
- 输出包含五级 verdict、severity、confidence、事实/推断/未知、支持证据 ID、反证 ID、攻击尝试、WAF 动作、后端到达、compromise 状态和建议。
- confidence 在完成校准前只是模型信心估计，不应解释为统计概率。
- 日志字段及请求内容均为不可信数据；模型必须忽略其中试图改变系统指令或工具权限的内容。
