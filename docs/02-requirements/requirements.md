# 需求规格说明（Requirements）

- 版本：2.0
- 状态：规划基线；具体实现按 Roadmap 分阶段验收
- 日期：2026-11-26

## 1. 产品目标

建设面向多厂商 WAF 的统一安全运营平台。首期接入阿里云 WAF（SLS）和腾讯云 WAF（CLS），但数据模型、字段注册、检测、调查和 Agent 层必须保持厂商无关。未来新增厂商时，主要增加 Provider Adapter 和厂商字段定义，不重写通用分析流程。

## 2. 用户角色

- 安全分析人员：告警研判、事件调查、证据审阅和报告生成。
- 平台管理员：数据源、凭据引用、任务和系统设置管理。
- 安全工程师：字段映射、检测规则和关联规则维护。
- 审计人员：查看查询、Agent 工具调用、审批和响应记录。

## 3. 范围边界

### 首期
- 阿里云 WAF → SLS、腾讯云 WAF → CLS。
- 只读日志接入、批量 Schema 画像、字段映射和统一事件。
- 基础统计、规则检测、跨源检索和调查。
- LangGraph 告警分诊、调查辅助和证据化报告。
- 小规模、低成本 PoC。

### 后续候选
- 其他云厂商、商业 WAF 和本地 WAF。
- API Security、Bot、Firewall、IPS/IDS、DDoS 等安全数据源。
- 威胁情报、案例管理、响应自动化。

### 首期排除
- QRadar 集成或替换、独立传统 SIEM。
- 全量原始日志复制。
- 无审批的云端写操作。
- 强制引入 Kafka、OpenSearch、Redis、TheHive、Shuffle、Kubernetes。
- 生产级 HA、多租户 SaaS。

## 5. Schema Discovery 与 Field Registry 要求

每个厂商/产品/日志类型都必须有独立的 Schema Profile 和 Field Registry。字段定义至少包括：
- 原始字段名、嵌套路径、数据类型和可空性。
- 字段说明、来源文档和语义置信状态（documented / observed / inferred / unknown）。
- 所属产品模块和日志类型。
- 是否敏感、脱敏方式和是否允许进入模型上下文。
- 候选统一字段、转换规则和转换版本。
- 观测覆盖率、枚举分布、首次/最近发现时间。

自动画像只能发现结构和统计关系，不能自行推断安全语义。未知字段和未知动作必须保留并标记 unknown，不得擅自映射为 allow、block 或攻击类型。

## 6. 统一事件模型要求

采用厂商无关的核心字段 + vendor extension：
- Identity：event_id、fingerprint、provider、vendor_product、account/tenant、region、source_id。
- Time：event_time、ingest_time、observed_time。
- Network：source/destination IP、port、protocol（可选）。
- HTTP/API：host、path、method、status、request_id（敏感值按策略处理）。
- Security：event_type、action、action_effectiveness、module、rule_id、rule_type、severity。
- Provenance：source_record_id、raw_reference、schema_version、parser_version、mapping_confidence。
- Extensions：厂商特有字段放入受控 JSON 扩展区，不污染通用核心字段。

必须区分：检测结果、规则动作、最终动作、测试/观察模式、HTTP 响应状态。不能仅凭 HTTP status 或字段缺失推断 allow/block。

## 7. AI Agent 需求

- Agent 仅处理经过筛选、脱敏和结构化的有限上下文。
- 工具调用必须有 allowlist、参数 Schema、时间范围和结果数限制。
- Agent 输出必须包含结论、证据 ID、理由、置信度、不确定性和人工复核标志。
- 日志、URL、User-Agent、Header、Cookie、请求参数和响应片段均视为不可信数据，不得解释为 Agent 指令。
- Agent 不持有云端管理员凭据；首期仅提供只读查询工具。
- 模型不得自行编造不存在的日志字段、规则或情报事实。

## 8. 非功能需求

- 安全：最小权限、凭据引用、加密传输、脱敏、审计和数据保留策略。
- 可扩展：厂商差异封装在 Adapter/Registry，核心模型和业务工作流稳定。
- 可靠性：分页、限速、重试、Checkpoint、幂等、迟到日志和可恢复回溯。
- 可观测：记录调用耗时、返回数、错误码、重试、成本和解析异常。
- 可解释：所有安全结论能够追溯到事件和查询证据。
- 成本：按数据源配置查询预算、采集上限、存储 TTL 和 LLM Token 预算。
- 可测试：每个厂商需有脱敏样例、契约测试、映射测试和回归测试。

## 9. 验收原则

每个新增厂商至少验收：
1. 连接、授权和查询范围正确。
2. 时间边界、分页和错误处理符合厂商 API 行为。
3. Schema Profile 可生成，敏感值不会泄漏。
4. 字段语义有来源依据，未知值保留 unknown。
5. 标准化事件保留来源和原始证据引用。
6. 共用检测/调查流程可处理该厂商事件。
7. 查询成本、数据量和失败恢复可观测。

## 10. 核心业务模式：分层攻击研判（v2.1 补充）

### 10.1 已确认决策
- 主要研判对象是 Security Incident（攻击事件），不是单条原始日志。
- 采用分层流程：原始日志/标准事件 → 告警信号 → 告警聚合组 → 攻击事件；必要时下钻单条日志。
- 单条日志是证据，告警信号是分析输入，Alert Group 用于降噪和组织相似告警，Security Incident 是调查、定级和报告的主要对象。
- AI 只提供研判结论和策略优化建议。当前不自动修改 WAF 策略、不自动封禁 IP、不执行云端写操作；安全人员在厂商控制台或既有变更流程中人工执行。

### 10.2 分层对象定义
| 对象 | 定义 | 主要 AI 研判对象 |
|---|---|---|
| Raw Record | 厂商日志服务中的原始记录 | 否，按需回查 |
| Normalized Event | 标准化后的单条安全相关记录 | 否，作为事实和证据 |
| Alert Signal | 厂商告警、规则命中或统计异常产生的信号 | 否，进入聚合 |
| Alert Group | 按实体、规则、行为特征和时间窗口归并的一组告警 | 初步分诊 |
| Security Incident | 经关联形成的攻击活动或疑似攻击活动 | **是，核心研判对象** |
| Investigation / Report | 针对事件的调查过程、证据链和结论 | 是 |
| Policy Recommendation | 针对 WAF 规则/策略的优化建议 | 是，仅建议不执行 |

Alert Group 不必然等于 Security Incident：一个告警组可能是正常业务误报；多个告警组也可能属于同一攻击事件。关联必须保留理由和置信度，不能只因 IP 相同就认定为同一攻击者或事件。

### 10.3 功能需求补充
| ID | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-027 | 告警聚合 | 按时间窗口、来源 IP、Host、URL/路径、规则、模块、请求标识和行为特征聚合；依据可配置、可解释 | P0 |
| FR-028 | 分层事件关联 | 将一个或多个告警组关联为攻击事件，保留实体关系、依据和置信度 | P0 |
| FR-029 | 事件分层研判 | 输出威胁判断、严重性、置信度、影响范围、支持证据、反证和未知项 | P0 |
| FR-030 | 按需证据下钻 | 在受限范围内查询标准事件和源端原始日志 | P0 |
| FR-031 | 业务误报研判 | 结合接口、参数模式、来源、频率、历史基线和业务上下文识别疑似正常业务 | P0 |
| FR-032 | 策略优化建议 | 对规则、URL、参数或业务范围提出建议，说明收益、误放风险和验证方式 | P0 |
| FR-033 | 人工反馈闭环 | 记录人工确认/驳回、最终分类、误报原因和处理结果 | P1 |
| FR-034 | 研判队列 | 按风险、置信度、影响范围和事件新鲜度组织待研判事件 | P1 |

### 10.4 研判结论分类
- Confirmed Malicious：证据足以支持真实恶意活动。
- Likely Malicious：有较强攻击迹象，但仍存在关键证据缺口。
- Likely Legitimate：更符合正常业务行为，可能属于误报或策略过敏。
- Confirmed Legitimate：经业务方/安全人员或可信业务上下文确认是正常行为。
- Inconclusive：证据不足、字段语义未知或证据相互矛盾。

不得把 WAF 告警命中直接等同于攻击成功，也不得把请求被拦截直接等同于攻击者已造成影响。需分别描述检测事实、WAF 动作、HTTP 响应和后端影响证据。

### 10.5 策略建议输出要求
每条建议必须包含关联事件、厂商/产品、规则 ID/类型、业务 Host/路径、观察到的问题和证据、建议范围与类型、预期收益、安全风险、验证测试、回滚考虑及状态。建议范围优先精细到规则/路径/参数，不默认建议全局关闭规则。建议状态与人工执行状态分离：Draft / Under Review / Accepted / Rejected / Implemented / Outcome Verified。平台不得伪造“已执行”状态。

### 10.6 P0 验收标准
1. 重复或高度相似告警可聚合，并可查看聚合依据和原始记录引用。
2. 告警组可形成事件候选；不能只凭 IP 相同关联。
3. 每个 AI 结论可追溯到事件、告警、标准事件或源端查询证据。
4. 支持恶意、疑似恶意、疑似正常、已确认正常和证据不足，不强制二元判断。
5. 字段缺失、动作语义未知或样本不足时降低置信度并说明限制。
6. 策略建议包含适用范围、误放风险和验证步骤；无自动写操作。
7. 人工可确认、驳回或修正研判结果并记录理由。
8. 可统计聚合前后数量、队列规模、人工复核比例、建议采纳情况和调查成本。

## 11. Web SOC 工作台与 AI 对话需求（v2.2 补充）

### 11.1 产品定位
平台必须提供统一 Web 工作台，供安全运营人员、分析人员和管理人员使用。工作台同时提供图形化操作和自然语言 AI 对话，两者共享身份权限、数据范围、查询服务、事件对象和证据引用。

### 11.2 页面与功能模块
| 模块 | 核心功能 | 主要用户 | 优先级 |
|---|---|---|---|
| SOC 总览 Dashboard | 告警量、事件量、威胁等级、研判状态、误报趋势、数据源健康、待处理队列 | 管理人员/安全负责人 | P0 |
| 安全日志查询 Log Explorer | 多云日志查询、时间范围、过滤、字段检索、结果表格、详情下钻、保存查询 | 安全分析人员 | P0 |
| 告警中心 Alert Center | 告警列表、聚合组、筛选、排序、聚合依据和成员查看 | 安全分析人员 | P0 |
| 攻击事件 Incident Center | 事件队列、详情、时间线、关联告警组、证据、研判结论和人工复核 | 安全分析人员 | P0 |
| AI 对话 AI Copilot | 自然语言查询日志、解释告警、调查事件、追问证据、生成报告和策略建议 | 安全分析人员/管理人员 | P0 |
| 策略建议 Recommendation Center | 建议列表、风险、适用范围、审核状态、人工执行记录和效果验证 | 安全工程师/负责人 | P0 |
| 报表中心 Reports | 安全运营报告、攻击趋势、误报分析、规则质量和处置效果 | 管理人员 | P1 |
| 系统管理 Administration | 用户、角色、数据源、查询权限、审计和配置管理 | 平台管理员 | P0 |

### 11.3 日志查询要求
1. 支持按云厂商、WAF 实例/数据源、时间范围、域名/Host、来源 IP、URL/路径、规则 ID/类型、检测模块和动作等字段过滤；具体过滤项由 Provider 能力和 Field Registry 决定。
2. 支持分页、排序、结果数量限制、时间范围限制和查询超时；展示查询耗时、数据源、命中数量和截断状态。
3. 展示标准化字段，并允许按权限查看厂商扩展字段和原始记录引用。
4. 支持从日志跳转到所属告警组和攻击事件，也支持从事件详情反向查看关联日志。
5. 支持保存个人/共享查询条件和常用查询模板；导出受角色权限、脱敏和审计策略控制。
6. 对高成本或宽范围查询显示风险，要求缩小条件或明确确认；禁止无限制查询。
7. URL、参数、Header、Cookie、Body 等敏感字段默认脱敏或隐藏，按权限和审计要求查看。

### 11.4 AI 对话要求
1. 用户可在独立 AI 对话页提问，也可从 Dashboard、日志、告警组或事件详情上下文中打开 AI Copilot。
2. 支持自然语言查询日志、分析攻击趋势、解释告警、调查事件、追问证据和生成报告。
3. 对话上下文可绑定数据源、时间范围、域名、告警组或 Security Incident；界面明确展示当前分析范围，允许修改或清除。
4. AI 先生成受控查询计划；对范围含糊、过宽或高成本请求，应解释并请求用户澄清/确认。
5. 回答区分事实、推断和未知项，提供可点击的日志、告警组、事件和证据引用。
6. 支持多轮追问、保存会话和将调查结果关联到事件。
7. 支持生成策略建议草稿，但不提供自动执行能力或厂商策略写入。
8. 对话、查询计划、工具调用摘要、证据引用和模型版本按审计策略留痕；敏感原始日志不得无控制地进入会话历史。

### 11.5 用户与权限
至少区分 Platform Admin、SOC Manager、Security Analyst、Read-only Viewer。权限覆盖页面模块、租户/数据源范围、字段敏感级别、原始日志查看、查询导出、AI 工具调用、建议审核和审计查看。所有权限在后端强制执行，不能只依赖前端隐藏按钮。

### 11.6 UI 非功能要求
- 关键页面采用服务端过滤和分页，不一次加载全部日志。
- 长耗时查询和 AI 调查展示状态、阶段、取消能力和失败原因（后端能力允许时）。
- 可采用流式 AI 输出，但最终结果必须完整且证据引用可用。
- 重要操作有审计记录；查询与模型调用可观测并可统计成本。
- 首期桌面 Web 优先。

### 11.7 UI P0 验收
1. 登录后展示符合角色权限的 Dashboard。
2. 分析人员可按时间、数据源和常见安全字段查询日志并查看详情。
3. 可从日志跳转到关联告警组/事件，并在事件详情查看证据链。
4. AI 对话可在明确上下文范围内查询和解释日志/事件，并返回可追溯引用。
5. AI 查询受权限、时间范围、结果上限和成本预算约束。
6. 管理人员可查看事件统计、研判分布、待处理情况和策略建议状态。
7. 策略建议只允许审核、接受/驳回和记录人工执行结果，不允许 AI 自动修改 WAF。
8. 权限拒绝、查询失败、数据截断和证据缺失均有明确提示。

## 12. UI 交互模式细化：独立页面 + 上下文联动（v2.3）

### 12.1 已确认的交互决策
- 主模式：独立页面 + 上下文联动。
- AI 助手呈现：全局可展开/收起的右侧对话面板。
- 同时保留独立的 AI 助手页面，支持完整的多轮调查和历史会话管理。
- 日志查询、告警组、攻击事件等业务页面均可将当前对象或用户选中的数据带入 AI 面板。
- 右侧面板是全局辅助工作区，不替代日志、告警和事件的正式详情页面。

### 12.2 全局应用布局
1. 左侧主导航：总览、日志查询、告警中心、攻击事件、AI 助手、策略建议、报表、系统管理。
2. 中央工作区：显示当前模块的完整业务内容。
3. 右侧 AI 面板：默认收起，用户主动展开；可在不同业务页面间保持打开状态。
4. 顶部全局栏：当前用户/角色、全局时间或数据范围提示、通知和 AI 面板入口。
5. 面板打开时应合理压缩中央工作区或覆盖显示；桌面端优先，具体响应式行为由 UI 原型确认。

### 12.3 右侧 AI 面板行为
- 在任何有权限的业务页面均可打开 AI 面板。
- 面板显示当前上下文标签，例如数据源、时间范围、Host、日志选择、告警组 ID 或事件 ID。
- 用户可明确添加/移除上下文、清空上下文或切换会话。
- 从日志列表选中单条或多条记录后，可选择“交给 AI 分析”；从告警组/事件详情可选择“让 AI 调查此对象”。
- 从页面筛选条件发起 AI 分析时，必须提示传递的是筛选条件/统计摘要还是具体记录，避免用户误以为全部日志内容都已发送给模型。
- 页面切换时，不得静默替换已有会话上下文；如需切换对象，应明确显示上下文变化，避免跨事件混淆。
- 用户可将面板中的调查升级到独立 AI 页面，保留会话、证据引用和已确认的数据范围。
- 支持面板收起后继续后台调查（若后端支持），重新打开时显示任务状态；用户可取消调查。

### 12.4 独立 AI 助手页面
独立页面提供完整调查空间：
- 左侧会话列表：新建、历史会话、会话标题、时间和关联事件。
- 中央对话区：多轮对话、结构化分析结果、调查阶段和报告。
- 上下文区：数据源、时间范围、Host、告警组/事件和已选日志等上下文清单。
- 证据区：日志记录、聚合统计、事件关系、查询引用和报告引用，可跳转回业务页面。
- 会话可关联一个或多个事件，但每次调查必须显示当前活动事件和查询范围。

### 12.5 UI 组件级交互要求
- 日志查询：支持选择记录、查看详情、保存过滤条件、将过滤条件或所选记录发送给 AI。
- 告警中心：支持打开告警组详情、查看成员和聚合依据、启动告警组研判。
- 攻击事件：支持事件时间线、证据列表、AI 调查、人工确认/修正结论。
- 策略建议：展示来源事件、规则/路径范围、证据、风险、验证与回滚方案；审核操作需填写或选择理由。
- Dashboard：图表和指标可下钻到相应日志/告警/事件列表，保留原始时间范围和过滤条件。
- AI 回答：证据链接跳转至对应日志、告警组或事件；跳转时保留原会话，面板上下文不被无提示覆盖。

### 12.6 角色视图
- SOC Manager：默认进入管理总览，关注事件态势、严重事件、待审核、误报趋势、策略建议状态和数据源健康。
- Security Analyst：默认进入工作队列/事件中心，关注待研判告警组、事件调查、日志查询和 AI Copilot。
- Platform Admin：进入系统管理，关注用户权限、数据源连接状态、查询用量和审计。
- Read-only Viewer：只查看授权范围内的 Dashboard、事件和报表，不能执行调查工具调用或审核操作，除非单独授予权限。

### 12.7 UI 验收补充
1. 右侧 AI 面板可从日志、告警、事件和 Dashboard 页面打开。
2. 从日志列表选中记录后，可明确选择将所选记录或筛选条件加入上下文。
3. 面板清楚展示当前上下文，支持移除、清空和切换。
4. 页面切换不会静默改变已有会话的调查对象。
5. 面板会话可升级到独立 AI 页面，且会话与证据引用保持一致。
6. AI 证据链接可返回具体业务对象，且不丢失原调查会话。
7. 管理人员和分析人员看到的默认首页及可执行操作受角色权限控制。

## 13. MVP UI 收敛：AI 威胁分析优先（v2.4）

### 13.1 产品定位调整
第一版定位为“AI 驱动的 WAF 日志威胁分析工具”，而不是功能完整的传统 SOC 管理平台。产品价值优先体现在读取日志、理解攻击行为、识别威胁和提供可追溯判断。UI 是分析入口和结果呈现层，不以页面数量或管理功能丰富度作为 MVP 成功标准。

### 13.2 MVP 最小页面
| 页面/区域 | 第一版功能 | 优先级 |
|---|---|---|
| 简易总览 | 数据源连接状态、最近查询/分析数量、威胁发现数量 | P1 |
| 日志查询 | 选择云厂商/数据源、时间范围、少量常用过滤条件、分页查看日志 | P0 |
| 日志详情 | 查看标准字段、必要的厂商原始字段、敏感字段脱敏 | P0 |
| AI 分析 | 对选中日志或受控查询结果发起分析；支持追问 | P0 |
| 分析结果 | 威胁结论、威胁类型、严重性、置信度、证据、反证和建议 | P0 |

第一版暂缓：复杂 Dashboard、完整告警工单、复杂案例管理、报表中心、策略审批工作流、用户自定义仪表盘和多层级组织管理。基础身份认证、后端权限、查询限制和审计仍不可省略。

### 13.3 核心用户流程
1. 用户选择 WAF 数据源和时间范围。
2. 用户查询日志，或选择一个预定义分析窗口/分析任务。
3. 后端执行限时、限量、可审计的日志查询与聚合，不把无限量原始日志直接交给模型。
4. AI 先基于统计摘要和标准化安全事件识别可疑模式；需要验证时再按需读取代表性日志和关联证据。
5. AI 输出威胁判断、证据、反证、置信度、影响范围、未知项和下一步建议。
6. 用户可点击证据回到日志详情，并继续追问；AI 不执行封禁或 WAF 策略写入。

### 13.4 AI 分析质量要求
- 分析对象优先为聚合后的行为簇/告警组或事件候选，不默认逐条把全部日志发送给 LLM。
- 采用“统计/规则预筛选 + AI 语义研判 + 按需证据下钻”的方式控制成本并提高可解释性。
- 结论必须区分事实、推断和未知；给出来源记录引用或可复现查询条件。
- 威胁结论沿用 Confirmed Malicious、Likely Malicious、Likely Legitimate、Confirmed Legitimate、Inconclusive。
- 至少识别首期 WAF 场景中的 SQL 注入、XSS、命令/路径探测、扫描、高频异常访问、Bot/自动化行为等候选类别；类别是否可判定取决于日志字段和证据，不得仅凭规则名称武断定性。
- 对“攻击尝试”“WAF 已拦截”“请求到达后端”“攻击成功/造成影响”分别描述，不混为一谈。
- 对样本不足、字段未知、日志查询被截断或时间范围不完整的情况明确降级置信度。
- 通过人工标注样本评估 Precision、Recall、误报率、漏报风险、证据有效率、单次分析成本和时延。

### 13.5 UI 交互保留决策
保留“独立页面 + 上下文联动”及“右侧可展开 AI 面板”，但 MVP 只实现最小闭环：日志页选中记录/查询结果 → 打开 AI 面板 → 查看分析结果和证据 → 跳回日志详情。独立 AI 页面先提供简洁会话工作区，不建设复杂会话运营能力。

### 13.6 MVP 验收
- 能从至少一个已验证 WAF 数据源查询日志并查看详情。
- 能对用户选定的日志样本或受控查询结果发起 AI 分析。
- 能识别代表性威胁场景，并输出证据支持的分类结论。
- 用户可以从结论定位到具体日志或查询证据。
- 查询范围、样本数量、截断情况、数据源和分析成本可见。
- 不足以判断时输出 Inconclusive，而不是强行给出攻击结论。
- AI 无权修改云端策略或执行封禁。

## 14. 分析任务触发与调度需求（v2.5）

### 14.1 已确认决策
第一版同时支持手动分析和定时自动分析。两者统一创建 Analysis Task，并复用同一日志查询、预筛选、聚合、证据构建和 AI 研判引擎。

### 14.2 功能需求
| ID | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-035 | 手动分析任务 | 用户指定数据源、时间范围、过滤条件或选定记录，预览范围后发起分析 | P0 |
| FR-036 | 定时调度 | 按数据源配置周期、窗口和启停状态，创建自动分析任务 | P0 |
| FR-037 | Checkpoint 与迟到日志 | 每个数据源独立水位，支持重叠窗口和幂等去重 | P0 |
| FR-038 | 统一任务状态 | 展示排队、运行、预算等待、成功、警告、失败和取消状态 | P0 |
| FR-039 | 预算与降级 | 限制查询量、频率、LLM 调用和成本；无候选时跳过模型调用 | P0 |
| FR-040 | 任务补跑与恢复 | 支持暂停、恢复、失败重试和指定范围补跑 | P1 |

### 14.3 手动分析 UI
用户可从日志查询页选中记录/行为簇发起分析，也可在 AI 面板指定数据源和时间范围。执行前展示范围、查询限制和成本提示；分析过程中展示任务状态，完成后展示结论与证据。

### 14.4 定时分析配置
第一版采用简单的全局/数据源级配置，不建设复杂工作流编排器。配置项包括：启用开关、数据源、运行间隔、分析窗口、重叠窗口、候选触发阈值、单次最大查询量、每日查询/模型预算。具体默认频率和窗口须在观察真实日志量、迟到情况和 SLS/CLS 计费后确定，不预先固定为生产承诺。

### 14.5 自动分析结果
定时任务生成与手动任务相同格式的分析报告。UI 提供最近任务、发现的候选威胁、风险等级、置信度、证据入口和失败/预算状态。自动分析只产生发现和建议，不自动封禁或修改 WAF。

### 14.6 P0 验收
1. 手动任务可指定范围并完成端到端研判。
2. 定时任务按数据源独立运行，支持启停和最近运行状态查看。
3. 两种任务使用同一工作流、结果结构和证据模型。
4. Checkpoint、重叠窗口、Fingerprint 去重可避免漏数和重复分析失控。
5. 失败任务不会错误推进成功水位；可安全重试。
6. 无威胁候选时可仅保留规则/统计扫描结果，不强制调用 LLM。
7. 查询与模型预算限制生效，超限有可见记录。

详细设计见 [核心分析引擎技术设计](../07-core-analysis-engine/core-analysis-engine-design.md)。新增/细化需求如下：

## 15. M0 统一范围与优先级基线（2026-11-26）

MVP 的权威范围、P0 威胁场景、领域对象、Analysis Task、AI Verdict、安全边界和 PoC 验收方案统一见 [M0 规划与设计基线](../01-project-planning/m0-baseline.md)。

本节用于解决历史需求中“完整 SOC 工作台”与“AI WAF 威胁分析 MVP”之间的优先级冲突：

1. **MVP P0** 仅要求：阿里云 WAF/SLS 与腾讯云 WAF/CLS 的只读接入能力；字段语义可追溯的标准化；确定性预筛选和告警/行为聚合；Evidence Pack；受控 LangGraph 研判；手动与定时统一 Analysis Task；最小日志查询、详情、AI 分析和证据定位；必要的认证、后端授权、预算、脱敏和审计。
2. **不属于 MVP P0 阻塞项**：复杂 SOC Dashboard、完整 Alert/Incident 工单生命周期、策略审批工作流、报表中心、用户自定义仪表盘、完整多层级组织管理和 SOAR。它们保留为后续规划，不应反向扩大首期验收范围。
3. 历史章节中与上述范围冲突的模块表、P0 标记和 UI 验收项，应按 M0 Baseline 的优先级解释；不得将历史文档中通用平台能力表述视为当前 MVP 必须全部交付。
4. P0 威胁场景的建议基线为 SQLi、XSS、命令/路径探测、扫描/异常访问、正常业务误报。场景能力必须由真实日志字段和样本验证；字段缺失或语义未知时不得强行定性。
5. 手动与定时分析共用同一 Analysis Task 和分析引擎。定时分析预算未配置前必须保持关闭；任何查询/模型调用均受后端硬限制。
6. 具体字段映射、动作语义、采集频率、重叠窗口、成本上限和模型效果阈值，均以 M1/M5/M7 的实测结果为准，不在需求文档中虚构数值目标。
