# 需求规格说明（Requirements）

- 版本：2.0
- 状态：规划基线；具体实现按 Roadmap 分阶段验收
- 日期：2026-11-26

## 1. 产品目标

建设面向多厂商 WAF 的统一安全运营平台。首期接入阿里云 WAF（SLS）和腾讯云 WAF（CLS），但数据模型、字段注册、检测、调查和 Agent 层必须保持厂商无关。未来新增厂商时，主要增加 Provider Adapter 和厂商字段定义，不重写通用分析流程。

## 2. 用户角色

- 安全分析人员：告警研判、事件调查、证据审阅和报告生成。
- 平台管理员：数据源、凭据引用、任务和系统设置管理。
- 安全工程师：字段映射、检测规则和关联规则维护。
- 审计人员：查看查询、Agent 工具调用、审批和响应记录。

## 3. 范围边界

### 首期
- 阿里云 WAF → SLS、腾讯云 WAF → CLS。
- 只读日志接入、批量 Schema 画像、字段映射和统一事件。
- 基础统计、规则检测、跨源检索和调查。
- LangGraph 告警分诊、调查辅助和证据化报告。
- 小规模、低成本 PoC。

### 后续候选
- 其他云厂商、商业 WAF 和本地 WAF。
- API Security、Bot、Firewall、IPS/IDS、DDoS 等安全数据源。
- 威胁情报、案例管理、响应自动化。

### 首期排除
- QRadar 集成或替换、独立传统 SIEM。
- 全量原始日志复制。
- 无审批的云端写操作。
- 强制引入 Kafka、OpenSearch、Redis、TheHive、Shuffle、Kubernetes。
- 生产级 HA、多租户 SaaS。

## 5. Schema Discovery 与 Field Registry 要求

每个厂商/产品/日志类型都必须有独立的 Schema Profile 和 Field Registry。字段定义至少包括：
- 原始字段名、嵌套路径、数据类型和可空性。
- 字段说明、来源文档和语义置信状态（documented / observed / inferred / unknown）。
- 所属产品模块和日志类型。
- 是否敏感、脱敏方式和是否允许进入模型上下文。
- 候选统一字段、转换规则和转换版本。
- 观测覆盖率、枚举分布、首次/最近发现时间。

自动画像只能发现结构和统计关系，不能自行推断安全语义。未知字段和未知动作必须保留并标记 unknown，不得擅自映射为 allow、block 或攻击类型。

## 6. 统一事件模型要求

采用厂商无关的核心字段 + vendor extension：
- Identity：event_id、fingerprint、provider、vendor_product、account/tenant、region、source_id。
- Time：event_time、ingest_time、observed_time。
- Network：source/destination IP、port、protocol（可选）。
- HTTP/API：host、path、method、status、request_id（敏感值按策略处理）。
- Security：event_type、action、action_effectiveness、module、rule_id、rule_type、severity。
- Provenance：source_record_id、raw_reference、schema_version、parser_version、mapping_confidence。
- Extensions：厂商特有字段放入受控 JSON 扩展区，不污染通用核心字段。

必须区分：检测结果、规则动作、最终动作、测试/观察模式、HTTP 响应状态。不能仅凭 HTTP status 或字段缺失推断 allow/block。

## 7. AI Agent 需求

- Agent 仅处理经过筛选、脱敏和结构化的有限上下文。
- 工具调用必须有 allowlist、参数 Schema、时间范围和结果数限制。
- Agent 输出必须包含结论、证据 ID、理由、置信度、不确定性和人工复核标志。
- 日志、URL、User-Agent、Header、Cookie、请求参数和响应片段均视为不可信数据，不得解释为 Agent 指令。
- Agent 不持有云端管理员凭据；首期仅提供只读查询工具。
- 模型不得自行编造不存在的日志字段、规则或情报事实。

## 8. 非功能需求

- 安全：最小权限、凭据引用、加密传输、脱敏、审计和数据保留策略。
- 可扩展：厂商差异封装在 Adapter/Registry，核心模型和业务工作流稳定。
- 可靠性：分页、限速、重试、Checkpoint、幂等、迟到日志和可恢复回溯。
- 可观测：记录调用耗时、返回数、错误码、重试、成本和解析异常。
- 可解释：所有安全结论能够追溯到事件和查询证据。
- 成本：按数据源配置查询预算、采集上限、存储 TTL 和 LLM Token 预算。
- 可测试：每个厂商需有脱敏样例、契约测试、映射测试和回归测试。

## 9. 验收原则

每个新增厂商至少验收：
1. 连接、授权和查询范围正确。
2. 时间边界、分页和错误处理符合厂商 API 行为。
3. Schema Profile 可生成，敏感值不会泄漏。
4. 字段语义有来源依据，未知值保留 unknown。
5. 标准化事件保留来源和原始证据引用。
6. 共用检测/调查流程可处理该厂商事件。
7. 查询成本、数据量和失败恢复可观测。

## 10. 核心业务模式：分层攻击研判（v2.1 补充）

### 10.1 已确认决策
- 主要研判对象是 Security Incident（攻击事件），不是单条原始日志。
- 采用分层流程：原始日志/标准事件 → 告警信号 → 告警聚合组 → 攻击事件；必要时下钻单条日志。
- 单条日志是证据，告警信号是分析输入，Alert Group 用于降噪和组织相似告警，Security Incident 是调查、定级和报告的主要对象。
- AI 只提供研判结论和策略优化建议。当前不自动修改 WAF 策略、不自动封禁 IP、不执行云端写操作；安全人员在厂商控制台或既有变更流程中人工执行。

### 10.2 分层对象定义
| 对象 | 定义 | 主要 AI 研判对象 |
|---|---|---|
| Raw Record | 厂商日志服务中的原始记录 | 否，按需回查 |
| Normalized Event | 标准化后的单条安全相关记录 | 否，作为事实和证据 |
| Alert Signal | 厂商告警、规则命中或统计异常产生的信号 | 否，进入聚合 |
| Alert Group | 按实体、规则、行为特征和时间窗口归并的一组告警 | 初步分诊 |
| Security Incident | 经关联形成的攻击活动或疑似攻击活动 | **是，核心研判对象** |
| Investigation / Report | 针对事件的调查过程、证据链和结论 | 是 |
| Policy Recommendation | 针对 WAF 规则/策略的优化建议 | 是，仅建议不执行 |

Alert Group 不必然等于 Security Incident：一个告警组可能是正常业务误报；多个告警组也可能属于同一攻击事件。关联必须保留理由和置信度，不能只因 IP 相同就认定为同一攻击者或事件。

### 10.3 功能需求补充
| ID | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-027 | 告警聚合 | 按时间窗口、来源 IP、Host、URL/路径、规则、模块、请求标识和行为特征聚合；依据可配置、可解释 | P0 |
| FR-028 | 分层事件关联 | 将一个或多个告警组关联为攻击事件，保留实体关系、依据和置信度 | P0 |
| FR-029 | 事件分层研判 | 输出威胁判断、严重性、置信度、影响范围、支持证据、反证和未知项 | P0 |
| FR-030 | 按需证据下钻 | 在受限范围内查询标准事件和源端原始日志 | P0 |
| FR-031 | 业务误报研判 | 结合接口、参数模式、来源、频率、历史基线和业务上下文识别疑似正常业务 | P0 |
| FR-032 | 策略优化建议 | 对规则、URL、参数或业务范围提出建议，说明收益、误放风险和验证方式 | P0 |
| FR-033 | 人工反馈闭环 | 记录人工确认/驳回、最终分类、误报原因和处理结果 | P1 |
| FR-034 | 研判队列 | 按风险、置信度、影响范围和事件新鲜度组织待研判事件 | P1 |

### 10.4 研判结论分类
- Confirmed Malicious：证据足以支持真实恶意活动。
- Likely Malicious：有较强攻击迹象，但仍存在关键证据缺口。
- Likely Legitimate：更符合正常业务行为，可能属于误报或策略过敏。
- Confirmed Legitimate：经业务方/安全人员或可信业务上下文确认是正常行为。
- Inconclusive：证据不足、字段语义未知或证据相互矛盾。

不得把 WAF 告警命中直接等同于攻击成功，也不得把请求被拦截直接等同于攻击者已造成影响。需分别描述检测事实、WAF 动作、HTTP 响应和后端影响证据。

### 10.5 策略建议输出要求
每条建议必须包含关联事件、厂商/产品、规则 ID/类型、业务 Host/路径、观察到的问题和证据、建议范围与类型、预期收益、安全风险、验证测试、回滚考虑及状态。建议范围优先精细到规则/路径/参数，不默认建议全局关闭规则。建议状态与人工执行状态分离：Draft / Under Review / Accepted / Rejected / Implemented / Outcome Verified。平台不得伪造“已执行”状态。

### 10.6 P0 验收标准
1. 重复或高度相似告警可聚合，并可查看聚合依据和原始记录引用。
2. 告警组可形成事件候选；不能只凭 IP 相同关联。
3. 每个 AI 结论可追溯到事件、告警、标准事件或源端查询证据。
4. 支持恶意、疑似恶意、疑似正常、已确认正常和证据不足，不强制二元判断。
5. 字段缺失、动作语义未知或样本不足时降低置信度并说明限制。
6. 策略建议包含适用范围、误放风险和验证步骤；无自动写操作。
7. 人工可确认、驳回或修正研判结果并记录理由。
8. 可统计聚合前后数量、队列规模、人工复核比例、建议采纳情况和调查成本。

## 11. Web SOC 工作台与 AI 对话需求（v2.2 补充）

### 11.1 产品定位
平台必须提供统一 Web 工作台，供安全运营人员、分析人员和管理人员使用。工作台同时提供图形化操作和自然语言 AI 对话，两者共享身份权限、数据范围、查询服务、事件对象和证据引用。

### 11.2 页面与功能模块
| 模块 | 核心功能 | 主要用户 | 优先级 |
|---|---|---|---|
| SOC 总览 Dashboard | 告警量、事件量、威胁等级、研判状态、误报趋势、数据源健康、待处理队列 | 管理人员/安全负责人 | P0 |
| 安全日志查询 Log Explorer | 多云日志查询、时间范围、过滤、字段检索、结果表格、详情下钻、保存查询 | 安全分析人员 | P0 |
| 告警中心 Alert Center | 告警列表、聚合组、筛选、排序、聚合依据和成员查看 | 安全分析人员 | P0 |
| 攻击事件 Incident Center | 事件队列、详情、时间线、关联告警组、证据、研判结论和人工复核 | 安全分析人员 | P0 |
| AI 对话 AI Copilot | 自然语言查询日志、解释告警、调查事件、追问证据、生成报告和策略建议 | 安全分析人员/管理人员 | P0 |
| 策略建议 Recommendation Center | 建议列表、风险、适用范围、审核状态、人工执行记录和效果验证 | 安全工程师/负责人 | P0 |
| 报表中心 Reports | 安全运营报告、攻击趋势、误报分析、规则质量和处置效果 | 管理人员 | P1 |
| 系统管理 Administration | 用户、角色、数据源、查询权限、审计和配置管理 | 平台管理员 | P0 |

### 11.3 日志查询要求
1. 支持按云厂商、WAF 实例/数据源、时间范围、域名/Host、来源 IP、URL/路径、规则 ID/类型、检测模块和动作等字段过滤；具体过滤项由 Provider 能力和 Field Registry 决定。
2. 支持分页、排序、结果数量限制、时间范围限制和查询超时；展示查询耗时、数据源、命中数量和截断状态。
3. 展示标准化字段，并允许按权限查看厂商扩展字段和原始记录引用。
4. 支持从日志跳转到所属告警组和攻击事件，也支持从事件详情反向查看关联日志。
5. 支持保存个人/共享查询条件和常用查询模板；导出受角色权限、脱敏和审计策略控制。
6. 对高成本或宽范围查询显示风险，要求缩小条件或明确确认；禁止无限制查询。
7. URL、参数、Header、Cookie、Body 等敏感字段默认脱敏或隐藏，按权限和审计要求查看。

### 11.4 AI 对话要求
1. 用户可在独立 AI 对话页提问，也可从 Dashboard、日志、告警组或事件详情上下文中打开 AI Copilot。
2. 支持自然语言查询日志、分析攻击趋势、解释告警、调查事件、追问证据和生成报告。
3. 对话上下文可绑定数据源、时间范围、域名、告警组或 Security Incident；界面明确展示当前分析范围，允许修改或清除。
4. AI 先生成受控查询计划；对范围含糊、过宽或高成本请求，应解释并请求用户澄清/确认。
5. 回答区分事实、推断和未知项，提供可点击的日志、告警组、事件和证据引用。
6. 支持多轮追问、保存会话和将调查结果关联到事件。
7. 支持生成策略建议草稿，但不提供自动执行能力或厂商策略写入。
8. 对话、查询计划、工具调用摘要、证据引用和模型版本按审计策略留痕；敏感原始日志不得无控制地进入会话历史。

### 11.5 用户与权限
至少区分 Platform Admin、SOC Manager、Security Analyst、Read-only Viewer。权限覆盖页面模块、租户/数据源范围、字段敏感级别、原始日志查看、查询导出、AI 工具调用、建议审核和审计查看。所有权限在后端强制执行，不能只依赖前端隐藏按钮。

### 11.6 UI 非功能要求
- 关键页面采用服务端过滤和分页，不一次加载全部日志。
- 长耗时查询和 AI 调查展示状态、阶段、取消能力和失败原因（后端能力允许时）。
- 可采用流式 AI 输出，但最终结果必须完整且证据引用可用。
- 重要操作有审计记录；查询与模型调用可观测并可统计成本。
- 首期桌面 Web 优先。

### 11.7 UI P0 验收
1. 登录后展示符合角色权限的 Dashboard。
2. 分析人员可按时间、数据源和常见安全字段查询日志并查看详情。
3. 可从日志跳转到关联告警组/事件，并在事件详情查看证据链。
4. AI 对话可在明确上下文范围内查询和解释日志/事件，并返回可追溯引用。
5. AI 查询受权限、时间范围、结果上限和成本预算约束。
6. 管理人员可查看事件统计、研判分布、待处理情况和策略建议状态。
