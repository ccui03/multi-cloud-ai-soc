# 需求规格说明（Requirements）

- 版本：0.1
- 状态：初稿，待确认

## 1. 用户角色

- 安全分析人员：查看告警、调查证据、生成报告。
- 安全负责人：审核高风险结论和响应动作。
- 平台管理员：配置数据源、权限、模型和运行参数。
- 审计人员：查看操作、审批和执行记录。

## 3. 非功能需求

- 安全：最小权限、凭据安全存储、传输加密、访问控制。
- 可审计：保存原始证据、分析过程、模型版本、工具调用和审批结果。
- 可靠性：支持重试、幂等、断点续传和失败队列。
- 可扩展性：采集适配器与分析、Agent、响应模块解耦。
- 可观测性：采集延迟、失败率、队列积压、API 错误和 Agent 执行状态可监控。
- 可解释性：重要结论必须关联日志证据或外部情报来源。
- 成本控制：支持数据保留策略、查询范围限制和 LLM 调用预算。

## 4. 统一事件字段（初步）

建议评估 OCSF 作为规范化参考。第一版至少考虑：
- event_id、event_time、ingest_time
- cloud_provider、account_id、region、waf_instance
- source_ip、source_port、destination_ip、destination_port
- hostname、uri_path、http_method、http_status
- action（allow/block/challenge 等）
- rule_id、rule_name、severity
- user_agent、request_id、trace_id
- raw_event、parser_version、schema_version

字段映射需使用真实脱敏日志样本验证，不应假定所有厂商都提供相同字段。

## 5. 验收原则

每项 P0/P1 功能需具备测试样例、预期结果和验收记录。AI 结论应能回溯到具体事件证据；没有证据时必须明确标注不确定性。
