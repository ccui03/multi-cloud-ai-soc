# 核心业务用例：WAF AI 攻击研判与安全运营

- 版本：1.0
- 状态：规划草案，待真实业务样本与安全团队评审
- 日期：2026-11-26

## 1. 产品目标与已确认决策

平台面向每天产生大量 WAF 告警和访问安全日志的运营场景，帮助安全人员判断哪些活动是真实威胁、哪些更可能是正常业务行为，并提供有证据的 WAF 策略优化建议。

已确认：
- 采用分层研判：先聚合告警，再关联攻击事件，必要时下钻单条日志。
- Security Incident 是主要 AI 研判对象；Alert Group 是告警降噪和事件候选层。
- AI 只提供建议，策略由人工审核和执行；平台当前不自动修改 WAF 配置或封禁 IP。
- 首期数据源为阿里云 WAF/SLS 和腾讯云 WAF/CLS。
- 原始日志默认留在源端，Agent 通过受控查询按需获取证据。

## 3. UC-01：WAF 告警聚合与降噪

**目标**：把海量、重复或高度相似的告警转化为可处理的告警组，降低逐条查看成本。

**触发**：新告警信号到达，或定时批处理窗口结束。

**输入**：标准化事件、厂商安全告警、时间、来源 IP、Host、URL/路径、规则 ID/类型、模块、动作和请求标识（以字段注册表实际确认内容为准）。

**流程**：
1. 幂等去重，识别重复投递和重复记录。
2. 按可配置时间窗口和多维行为特征生成候选分组。
3. 计算组内数量、独立来源、目标路径、规则分布、动作分布和时间趋势。
4. 保留成员事件引用、聚合规则版本和分组理由。
5. 对关键字段缺失或语义未知的事件单独标记，不强制并组。

**输出**：Alert Group、成员事件引用、统计摘要、分组依据和质量标记。

**验收**：同一输入和规则版本可复现聚合结果；可查看成员事件并拆分错误分组；不因单一 IP 相同就无条件合并；聚合统计可审计。

**限制**：时间戳不可靠、字段语义未知或来源字段缺失时，降低聚合强度并标记限制。

## 4. UC-02：攻击事件分层研判

**目标**：判断一个或多个告警组代表真实攻击、疑似攻击、正常业务还是证据不足。

**触发**：高优先级告警组生成、关联引擎形成事件候选或分析人员手动发起调查。

**输入**：告警组、统计摘要、代表性事件、实体关系、时间线、WAF 检测结果、模块动作、最终动作和测试/观察模式等语义字段。

**流程**：
1. 检查证据完整性、时间范围、字段语义和数据源状态。
2. 生成待验证假设，例如漏洞利用、扫描探测、误报或业务参数触发规则。
3. 按需查询关联事件和少量源端原始样本。
4. 同时寻找支持证据、反证和替代解释。
5. 评估攻击行为、WAF 防护动作、潜在影响和未确认事项。
6. 输出分层结论、严重性、置信度和调查理由。

**结论分类**：
- confirmed_malicious：证据支持真实恶意活动。
- likely_malicious：攻击迹象较强，但仍有关键缺口。
- likely_legitimate：更符合正常业务行为。
- confirmed_legitimate：已有可信业务上下文或人工确认。
- inconclusive：证据不足或相互矛盾。

**验收**：结论引用可解析证据；严重性与置信度分开；不把 WAF 命中等同攻击成功，不把 WAF 拦截等同后端一定未受影响；证据不足时允许 inconclusive。

## 5. UC-03：正常业务误报识别

**目标**：识别正常业务请求触发 WAF 规则的情况，避免简单放宽规则造成防护缺口。

**触发**：某规则/URL/参数持续产生高频告警，或分析人员报告疑似误报。

**输入**：告警组和代表性请求样本、Host、路径模板、方法、参数结构摘要、规则和模块信息、来源类型、频率、历史基线，以及经授权提供的业务说明。

**流程**：
1. 定位误报集中在哪些规则、路径、参数和业务时间段。
2. 比较请求模式稳定性、来源分布和历史变化。
3. 检查扫描、探测、异常编码、攻击载荷等恶意迹象。
4. 对照业务方提供的接口语义和正常样本。
5. 给出疑似正常或证据不足，不因没有攻击证据就自动认定正常。

**输出**：疑似误报范围、支持/反对证据、影响请求量、需业务确认事项和置信度。

**验收**：误报结论必须有正向业务或行为证据；不自动创建全局白名单；考虑共享出口、CDN、NAT、代理和爬虫等因素。

## 6. UC-04：事件调查与证据下钻

**目标**：在有限查询预算内验证事件假设并构建可复现证据链。

**流程**：
1. Agent 提出最小必要查询计划。
2. 工具层校验数据源、时间范围、过滤条件、结果上限和预算。
3. 优先查询聚合统计和标准化事件；只有需要验证具体请求细节时才回查原始日志。
4. 将查询条件、时间范围、返回数量、数据源和结果引用写入审计记录。
5. 更新 Evidence Pack 和事件时间线。

**验收**：无任意 DSL、无限时间范围或无限结果查询；原始日志文本不构成 Agent 指令；结论可追溯到具体查询与证据。

## 7. UC-05：WAF 策略优化建议

**目标**：针对持续误报或策略不合理问题，给出范围明确、风险可见、可由人工审核执行的建议。

**输入**：相关事件、规则 ID/类型、Host/路径/参数范围、统计结果、业务确认信息和安全证据。

**流程**：
1. 定位具体规则及受影响业务范围。
2. 汇总误报比例、样本模式和可能的攻击混淆点。
3. 比较规则例外评估、参数级/路径级精细调整、规则敏感度复核等建议。
4. 分析潜在绕过风险、受影响资产和测试范围。
5. 生成建议草案，由安全人员和业务负责人审核。
6. 人工在 WAF 控制台或既有变更流程中执行；平台记录外部变更引用和效果。

**输出**：建议类型、目标规则、适用范围、证据、业务收益、安全风险、验证测试、观察窗口和回滚考虑。

**状态**：Draft / Under Review / Accepted / Rejected / Implemented / Outcome Verified。

**验收**：不默认建议关闭整个防护；建议不等于已执行；平台没有 WAF 写凭据和自动执行路径；记录人工处理结果及变更后观察结论。

## 8. UC-06：跨域名/跨云攻击关联（P1）

识别同一攻击活动针对多个业务站点或不同云平台的行为。关联信号包括时间邻近、来源实体、目标 Host、路径模板、规则类别、请求模式、行为序列及可信情报（如启用）。IP 可能是 NAT、代理、CDN 或共享出口；单一 IP 相同不是充分关联条件。跨厂商字段必须先完成语义标准化。

## 9. UC-07：WAF 规则质量与攻击趋势（P1）

分析规则/模块告警量和趋势、Host/路径/云厂商分布、人工确认误报率、建议采纳率和变更后效果，以及新出现的攻击模式。输出趋势报告、规则质量排名和重点调查对象；不能仅以命中量高低判定规则质量。

## 10. 统一 AI 研判报告结构

1. 事件摘要和调查范围。
2. 研判结论、严重性和置信度。
3. 观测事实（Observation）。
4. 分析推断（Inference）。
5. 支持证据与反证。
6. 攻击时间线和涉及实体。
7. WAF 检测结果与实际防护动作（语义明确时）。
8. 业务误报可能性和待业务确认事项。
9. 策略优化建议及风险、测试和回滚考虑。
10. 数据缺口、查询范围、抽样方法和调查限制。

## 11. MVP 评估指标

先建立人工标注的脱敏样本集，再确定目标阈值。至少评估聚合降噪率和错误合并率、事件关联准确性、各研判分类 Precision/Recall、Inconclusive 占比、证据引用有效率、反证覆盖率、无依据结论比例、人工审核通过率、修订率、平均调查耗时、策略建议接受率和效果验证率，以及每千条日志查询成本和每个事件模型成本。不得仅用模型自评或未经人工标注的结果宣称研判准确率。

## 12. Web 工作台与 AI 对话用例

### UC-08：安全日志查询工作台（P0）
**目标**：安全分析人员无需登录多个云厂商控制台，即可在统一界面查询多云 WAF 日志。

**流程**：选择云厂商/数据源与时间范围 → 设置 Host、来源 IP、URL、规则、动作等过滤条件 → 后端校验权限和查询预算 → 查询源端日志服务 → 分页展示标准化结果 → 打开单条详情或跳转告警组/事件。

**输出**：结果列表、标准字段、厂商扩展信息（按权限）、查询耗时、命中/截断提示和原始记录引用。

**验收**：支持分页与服务端过滤；跨厂商字段语义差异有明确呈现；不支持的过滤能力不能伪装成支持；敏感字段按角色脱敏；查询范围和执行结果可审计。

### UC-09：AI 自然语言安全分析（P0）
**目标**：使用自然语言完成日志检索、告警解释、事件调查和策略建议。

示例问题：
- “过去 24 小时哪些 SQL 注入告警最集中？”
- “分析这个告警组，判断更像攻击还是正常业务。”
- “为什么这个事件被判断为疑似恶意？列出支持证据和反证。”
- “哪些 WAF 规则可能对正常业务产生误报？给出调整建议。”

**流程**：用户提问 → 解析会话上下文和权限 → 生成受控查询计划 → 校验查询范围与预算 → 调用只读查询工具 → 构建 Evidence Pack → Agent 研判 → 返回结论与证据链接 → 用户追问或保存调查。

**验收**：自然语言问题不能绕过 RBAC；查询范围不明确时主动澄清；回答包含证据引用和数据范围；区分事实/推断/未知；不能执行云端写操作。

### UC-10：管理人员安全态势总览（P0）
**目标**：管理人员快速掌握安全运营状态，不必逐条阅读日志。

展示内容：告警总量、聚合后告警组、攻击事件数、研判结论分布、严重事件、待人工复核队列、疑似误报趋势、策略建议状态和数据源健康状态。

**验收**：每个指标有明确统计口径和时间范围；可下钻到事件列表；区分告警量与事件量；管理角色只能查看授权数据范围。

### UC-11：事件上下文 AI Copilot（P0）
用户从告警组或事件详情打开 AI 对话时，自动带入事件 ID、关联告警组、时间范围和证据摘要。界面明确显示上下文，允许用户调整范围。AI 可解释事件、补充调查、追问证据和生成报告。切换事件时必须显式更新上下文，防止旧事件上下文污染新调查。

### UC-12：策略建议审核与运营反馈（P0）
安全人员在工作台查看 AI 建议，检查目标规则、适用 Host/路径/参数、证据、预期收益、绕过风险、验证方案和回滚考虑；随后接受、驳回或要求补充。实际策略变更由人工在外部控制台/流程执行，平台只记录外部变更单、执行时间、执行人和观察结果。

## 13. UI 交互流程用例（v2.3）

### UC-13：全局右侧 AI 助手面板（P0）
**用户目标**：在查看日志、告警或攻击事件时，不离开当前工作页面即可向 AI 提问。

**主流程**：
1. 用户在任意有权限的业务页面点击全局 AI 助手入口。
2. 右侧面板展开，并显示当前页面可提供的上下文。
3. 用户确认上下文或添加所选日志/告警组/事件。
4. 用户提问；Agent 根据当前身份和上下文生成受控查询计划。
5. UI 展示分析阶段、数据范围、证据和结论。
6. 用户可追问、清除上下文、取消调查或将会话打开到独立 AI 页面。

**异常流程**：上下文无权访问、查询范围超预算、数据源不可用或证据不完整时，显示具体原因并允许用户调整范围。

**验收**：面板可跨业务页面使用；上下文不会静默串线；对话与工具调用仍受后端权限和查询预算约束。

### UC-14：日志选择后发起 AI 研判（P0）
用户在 Log Explorer 选中一条或多条日志，点击“交给 AI 分析”。UI 明确提示加入上下文的是选中记录、记录引用还是当前筛选条件的统计摘要。AI 基于实际传入内容分析；若需要扩大查询范围，必须通过受控 Query Planner 执行并显示查询范围。验收：模型不得声称分析了未传入或未查询的数据。

### UC-15：AI 调查升级为独立工作区（P1）
用户从右侧面板选择“在 AI 助手页面打开”，进入独立 AI 页面，保留会话 ID、调查上下文、已生成证据和历史消息。验收：升级前后会话一致，证据链接有效，权限在每次工具调用时重新校验。
